# 練習デイリーノート＋紙ノートの写真読み取り 設計書

**作成日:** 2026-11-08
**対象:** 卓球記録ノート（一般公開済みPWA）

---

## 1. 目的とスコープ

### 解決したい問題

アプリは試合しか記録できない。練習は毎日あるのに、その中身（何を練習し、何ができて、何が課題だったか）が残らない。
また、子どもは練習中にスマホを使わないため、アプリへの直接入力だけでは記録が続かない。

### ゴール

- 練習の記録を**少ない操作で続けて残し、データとして貯める**
- **紙に書いて、あとで写真を撮って取り込む**ことができる

### 決めたこと

| 項目 | 決定 |
|---|---|
| 記録する項目 | 練習時間・練習内容・意識すること・出来栄え（1〜5）・一言（2026-11-08 改訂。最初の版は技術タグ＋できた／課題） |
| 練習内容・意識すること | よくあるものをアプリが用意し、選手ごとに自分の項目を足したり、用意された項目を非表示にしたりできる |
| 紙で取り込む対象 | 練習だけ（試合は今までどおりアプリで入力） |
| 写真を撮る人 | 子ども本人 |
| 紙の単位 | 1週間1枚（曜日ごとの欄。写真は週1回） |
| チェック欄の読み取り | スマホ内で処理（無料・写真を外に出さない） |
| 手書きの一言の読み取り | オープンなAIの無料枠（Cloudflare Workers AI）。有料化の段階で読み取り役を差し替えられる形にする |
| 入口 | 下のナビに「練習」を追加（日記／練習／記録／分析）。既存画面の中身は変えない |

Gemini API は使わない。規約に「18歳未満が使う可能性のあるサービスでの利用禁止」があり、無料枠では送った内容がGoogleの製品改善に使われ、人が読むこともあるため（2026-03-23 発効版で確認）。

### スコープ外

- 練習と試合をつなぐ分析（データが貯まってから別途）
- 試合記録シートの写真読み取り
- 写真の保存
- 指導者が複数人分をまとめて取り込む機能
- 有料プランの課金

## 3. データモデル

`sql/05-practice-notes.sql` を新規作成する。

```sql
CREATE TABLE IF NOT EXISTS practice_notes (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  player_id uuid NOT NULL REFERENCES players(id) ON DELETE CASCADE,
  date date NOT NULL,
  minutes int,                              -- 練習時間（分）。休みは 0、未記入は null
  practiced jsonb NOT NULL DEFAULT '[]',    -- 練習した技術
  good jsonb NOT NULL DEFAULT '[]',         -- ◎できた
  issues jsonb NOT NULL DEFAULT '[]',       -- △課題
  memo text,                                -- 一言
  source text NOT NULL DEFAULT 'app',       -- 'app' | 'paper'
  created_at timestamptz NOT NULL DEFAULT now(),
  updated_at timestamptz NOT NULL DEFAULT now(),
  UNIQUE (player_id, date)
);
```

- **1日1件**（`UNIQUE (player_id, date)`）。保存は upsert。同じ日を開けば前の内容を直せ、紙の取り込みもやり直せる
- `good` と `issues` に入る技術は、必ず `practiced` にも入れる（アプリ側で保証）
- RLS は matches と同じ形（`player_id IN (SELECT id FROM players WHERE account_id = auth.uid())`）
- `updated_at` は既存の `set_updated_at()` トリガーを使う

### 練習内容・意識すること・出来栄え（2026-11-08 改訂）

`sql/06-practice-items.sql` で列を2つ足す。

| 列 | 中身 |
|---|---|
| `practice_notes.items` | 選んだ項目と出来栄え。`[{"kind":"menu","label":"フォア打ち","rating":4}]`。kind は `menu`=練習内容 / `focus`=意識すること、rating は 1〜5（未評価は null） |
| `players.practice_items` | 選手ごとの項目の設定。`{"custom":{"menu":[],"focus":[]},"hidden":{"menu":[],"focus":[]}}` |

- 最初の版の列（`practiced` / `good` / `issues`）は読み込み時に `items` へ変換する（できた=4、課題=2、練習しただけ=未評価）。新しい保存では空にする
- 用意する項目は `js/practice-tags.js` の `PRESET_ITEMS`
  - 練習内容（14）: フォア打ち・バック打ち・ツッツキ・ドライブ・ブロック・フットワーク・サーブ・レシーブ・3球目攻撃・台上（ストップ・フリック）・多球練習・オール・ゲーム練習・体力・筋トレ
  - 意識すること（12）: 打点・足を動かす・体重移動・回転をかける・コースを狙う・早く戻る・低いボール・前陣で打つ・相手をよく見る・ミスを減らす・声を出す・集中
- 画面に出す順は、自分で足した項目 → 非表示にしていない用意済みの項目
- 自分の項目は種類ごとに20個まで、1つ20文字まで

### 練習時間の選択肢

| 表示 | 保存値（minutes） |
|---|---|
| 休み | 0 |
| （未選択） | null |
| 〜1h | 60 |
| 1.5h | 90 |
| 2h | 120 |
| 2.5h | 150 |
| 3h〜 | 180 |

## 4. 段階1：アプリでの入力

### 画面（`screen-practice`）

```
┌──────────────────────────────┐
│ 練習ノート                     │
│ 体験 太郎 ・ 今週 3日・6時間    │
│ ◀  11/8(日)  ▶               │
│ 練習時間 [休み][〜1h]...[3h〜]  │
│ 練習内容          項目を編集    │
│ [チキータ][フォア打ち][サーブ]… │
│ 意識すること       項目を編集    │
│ [打点][足を動かす]…            │
│ 出来栄え（1=できなかった…5=よくできた） │
│ 練習 サーブ    (1)(2)(3)(4)(5) │
│ 意識 打点      (1)(2)(3)(4)(5) │
│ 一言 [________________]       │
│ [ 保存 ]                      │
│ ─ 最近のノート ─              │
│ 11/7 2h サーブ4 打点2          │
└──────────────────────────────┘
```

- 日付の初期値は今日。◀▶で前後の日へ。その日のノートがあれば読み込む
- 項目をタップすると選ばれ、「出来栄え」に行が出る。もう一度タップで外れる（出来栄えも消える）
- 出来栄えは1〜5を1タップ。同じ数字をもう一度押すと未評価に戻る
- 「項目を編集」で、自分の項目の追加・削除と、用意された項目の表示／非表示を切り替える（下から出るダイアログ。保存するまで反映しない）
- 最近のノートをタップするとその日を開く

| ファイル | 役割 |
|---|---|
| `js/practice-tags.js`（新規） | 用意する項目・練習時間・出来栄えの定数と、ノートを扱う純粋な関数 |
| `js/practice-notes.js`（新規） | Supabase の list / upsert / remove。`js/matches.js` と同じ書き方 |

## 5. 段階2：紙シートとチェック欄の読み取り

### 紙シート（A4縦・様式ID `TN-P01-v1`）

- 既存の試合記録シートの見た目と、四隅の黒い目印を踏襲する
- 上部：名前・「◯月◯日の週」（手書き。人が見るためのもの）・様式ID
- 曜日ごとの欄×7（月〜日）。各欄に、練習時間の○（6個）、一言の下線
- **2026-11-08 改訂により要再設計**: 項目が選手ごとに違い、出来栄えが1〜5になったため、紙はその選手の項目を印刷する形（アプリから選手ごとのシートを出す）と、1〜5の記入方法を段階2の着手時に決め直す
- 座標（mm）は `js/practice-sheet-layout.js` に**一か所だけ**定義し、シートの描画と読み取りの両方が使う
- テンプレート `docs/assets/templates/paper-practice-sheet.html` が layout から描画し、`scripts/build-practice-sheet.mjs`（Playwright の `page.pdf()`）でPDFにする。公開用に `/practice-sheet.pdf` を置き、練習画面から開ける

### 読み取り（`js/sheet-reader.js`）

スマホ内で完結し、外部ライブラリは使わない。

1. カメラで撮影（`<input type="file" accept="image/*" capture="environment">`）
2. canvas で縮小・グレースケール化し、四隅の目印（黒い正方形）を探す
3. 4点から射影変換で用紙をまっすぐにする（8×8の連立方程式を自前で解く）
4. layout の各□・○の内側の暗さを測り、同じ行の空欄と比べて記入を判定する。判定の境目に近いものは「自信なし」とする
5. 練習時間は6つの○のうち最も暗いもの。どれも薄ければ未記入
6. 各日の一言の範囲を画像として切り出す

純粋な関数（画像データ → 結果）に分け、テストで合成画像を読ませられるようにする。

### 確認画面

- 週の選択。初期値は直近の月曜始まりの週。◀▶で変更
- 7日分のカードに読み取り結果を出し、段階1と同じタップ切り替えで直せる。「自信なし」の欄は黄色
- 一言は切り出した画像を表示し、手で入力できる（段階3で自動入力）
- 何も書かれていない日は保存しない。保存は upsert（`source = 'paper'`）
- 目印が見つからないときは「用紙全体が入るように、明るい所で撮ってください」と出して撮り直し

## 6. 段階3：手書きの一言をAIで読む

### 精度の試し

実装の前に、実際に手書きした一言の写真で Workers AI の画像対応モデルを2〜3個比べる（`scripts/spike-memo-ocr.mjs`）。
読めないレベルなら段階3は見送り、段階2の「画像を見ながら手入力」のままにする。

### 仕組み

| ファイル | 役割 |
|---|---|
| `api/read-memo.js`（新規・Vercelの関数） | 利用者のトークンを Supabase の `/auth/v1/user` で確かめてから読み取る。1回最大7枚・1枚の大きさに上限 |
| `api/_lib/memo-providers.js`（新規） | 読み取り役の差し替え口。`MEMO_PROVIDER=workers-ai`。有料化の段階で別のAIに替えられる |

- 秘密情報（Cloudflare のアカウントID・APIトークン・モデル名）は Vercel の環境変数に置き、リポジトリには書かない
- 写真は保存しない
- AIが失敗しても保存は止めない（一言が空欄になるだけ）
- `privacy.html` に、一言の画像を読み取りのためだけに Cloudflare へ送り、保存しないことを書く
