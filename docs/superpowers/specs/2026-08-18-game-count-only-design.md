# ゲームカウントのみの記録（かんたん入力） 設計書

**作成日:** 2026-08-18
**きっかけ:** 利用者からの改善要望メール（要望①）
**対象:** 卓球記録ノート（一般公開済みPWA）

> ゲーム内のポイントを省略して、ゲームカウントのみで記録できるととても利用しやすいです。
> ゲーム練習などでは、ポイントまで記憶することができないので、簡易な入力ができると大変助かります。

---

## 1. 目的とスコープ

### 解決したい問題

現在スコアは各セットの点数を必ず入力する設計になっており、
`score` に `"11-8, 11-6, 9-11, 11-7"` という文字列で保存している。
セットカウントはこの文字列から逆算している（`countSets()`）。

しかし**ゲーム練習では点数まで覚えていられない**。
点数を思い出せないと記録自体を諦めることになり、
「練習でこそ数を稼げるはずの記録」が残らない。

### ゴール

ポイントを省略し、**ゲームカウント（例：3−1）だけで試合を記録できる**ようにする。

### スコープ外

- 3ゲームマッチ／5ゲームマッチといった試合形式の設定（別途の要望として扱う）
- 点数を使った新しい分析（接戦率など）

---

## 2. データモデル

`sql/04-add-game-count.sql` を新規作成する。

```sql
ALTER TABLE matches ADD COLUMN IF NOT EXISTS games_won  int;
ALTER TABLE matches ADD COLUMN IF NOT EXISTS games_lost int;
```

どちらも nullable。値の意味は次のとおり。

| 記録方法 | `score` | `games_won` / `games_lost` |
|---|---|---|
| 詳細（従来） | `"11-8, 11-6, 9-11, 11-7"` | null |
| かんたん（新規） | null | `3` / `1` |

**既存データは無影響。** `games_*` が null の試合は、これまでどおり
`score` からセットカウントを逆算して表示する。

### JS側のプロパティ名

`rowToMatch()` で DB のスネークケースからキャメルケースに変換する。
既存の `opponent_gender` → `gender` と同じ流儀に揃える。

| DB列 | JSプロパティ |
|---|---|
| `games_won` | `gamesWon` |
| `games_lost` | `gamesLost` |

`countSets()` など表示側はすべて `gamesWon` / `gamesLost` を参照する。
ここを取り違えると常に `undefined` になり、かんたん記録が
「どちらも無い」扱いに落ちて `勝ち`/`負け` 表示になってしまう。

---

## 3. 記録フォーム

スコア欄の先頭に入力方法の切り替えを置く。既存の利き手・性別と同じ2ボタン形式にする。

```
スコア
 ┌─────────────┬─────────────┐
 │   詳細       │  かんたん    │   ← 2ボタン切り替え
 └─────────────┴─────────────┘
```

- **詳細**：従来どおりドラムロールで各セットの点数を入力
- **かんたん**：ドラムロールを隠し、ゲームカウントだけを入力

### かんたん入力のUI

0〜4のタップボタンを自分・相手それぞれに並べる。

```
自分   [0] [1] [2] [3] [4]
相手   [0] [1] [2] [3] [4]
```

ドラムロールではなくタップボタンにする理由は、**ゲームカウントは0〜4の
狭い範囲**で、スクロールして止めるより1タップの方が速いため。
点数（0〜20超）にドラムロールが向くのとは要件が違う。

### モードの記憶

選んだモードは localStorage（`pingpong_score_mode`）に保存し、次回の記録画面に引き継ぐ。
練習中心の利用者が毎回選び直さなくて済むようにする。既定は「詳細」。

### 入力の検証

かんたんモードでは **`games_won` と `games_lost` が同じ値だと勝敗が決まらない**。
この場合は保存せず、「どちらが勝ったか決まりません」と画面内に表示する。
（0−0 のまま保存しようとした場合も同じ扱いになる）

詳細モードの検証は従来どおり変更しない。

### モード切替時に反対側の値を必ず消す

**保存時は、選ばれていないモードの値を必ず null にする。**

| 保存時のモード | `score` | `games_won` / `games_lost` |
|---|---|---|
| 詳細 | 入力値 | **null** |
| かんたん | **null** | 入力値 |

これを怠ると、詳細で記録した試合を編集してかんたんに切り替えたとき
`score` と `games_*` の両方が残り、`countSets()` が `games_*` を優先するため
**カードの表示と実際の点数が食い違う**。逆方向でも同じことが起きる。

### かんたんモードで隠すもの

- 各セットのドラムロール（`#score-inputs`）
- **「＋ セット追加」ボタン** — 押しても意味がなく、押せると誤解を生む

また `showScreen('record')` は `syncAllWheels()` を呼ぶが、かんたんモードでは
ドラムロールが存在しない。**要素が無くてもエラーにならないことを確認する。**

## 4. 表示への反映

### 4.1 セットカウントの算出

`countSets(m)` を、`games_*` があればそれを優先するように変更する。

```js
function countSets(m) {
  // かんたん記録はゲームカウントをそのまま使う
  if (m.gamesWon != null && m.gamesLost != null) {
    return { mine: m.gamesWon, theirs: m.gamesLost, hasCount: true, hasSetLines: false };
  }
  const sets = parseSets(m.score);
  ...
  return { mine, theirs, hasCount: sets.length > 0, hasSetLines: sets.length > 0 };
}
```

`hasScore` を `hasCount`（カウントが出せるか）と `hasSetLines`（各セットの点数があるか）に
分ける。この2つは従来同じ意味だったが、かんたん記録では**カウントはあるが点数はない**
という状態が生まれるため、区別が必要になる。

### 4.2 試合カード

中央の表示を3通りに分ける。

| 状態 | 中央の表示 |
|---|---|
| 各セットの点数がある | 従来どおり点数を縦積み |
| かんたん記録（カウントのみ） | `−` のみ |
| どちらも無い（過去の記録） | 従来どおり `勝ち` / `負け` |

かんたん記録のカードは「体験太郎 **3 − 1** 佐藤健」となり、
**左右対称のレイアウトはそのまま保たれる**。

ここで `勝ち`/`負け` を出さないのは、両脇にカウントが出ているため
重複して読みにくくなるからである。

## 5. 分析への影響

**コード変更は不要。**

`renderAnalysis()` は `win` / `type` / `age` / `gender` / `tags` だけを見ており、
`score` を一切参照していないことを確認済み。
したがって、かんたん記録の試合も**そのまま既存の集計すべてに含まれる**。

これは意図した挙動である（利用者は練習試合で使うと述べており、
それが勝率に入らないなら記録する意味が薄れる）。

点数を必要とする分析を将来作る場合は、そのときに
「各セットの点数がある試合だけ」で計算すればよい。

---

## 6. CSVエクスポート

`スコア` 列の後ろに **`ゲームカウント` 列**を追加する。

- 詳細記録：`スコア` に点数、`ゲームカウント` に逆算した `3-1`
- かんたん記録：`スコア` は空、`ゲームカウント` に `3-1`

両方の記録方法で `ゲームカウント` が必ず埋まるので、
表計算で並べたときに比較しやすくなる。

### 適用順序

**SQLを先に実行してからデプロイする。** 列が無い状態で新しいコードを
デプロイすると、試合の保存が Supabase 側のエラーで失敗する
（第1段のプロフィール拡張と同じ理由）。

## 8. テスト

| 対象 | 確認内容 |
|---|---|
| モード切替 | 詳細⇄かんたんで入力欄が切り替わる |
| モードの記憶 | 記録画面を開き直しても前回のモードが残る |
| かんたん保存 | 3−1で保存 → カードが「3 − 1」表示、点数は出ない |
| 勝敗の判定 | かんたん記録の勝敗が正しく入る |
| 同値の拒否 | 2−2 で保存しようとすると止まり、理由が表示される |
| 編集の往復 | かんたん記録を編集で開くとかんたんモードで復元される |
| **詳細→かんたんへの切替** | **点数で記録した試合を編集してかんたんに変えると `score` が消え、カードが二重表示にならない** |
| **かんたん→詳細への切替** | **逆方向でも `games_*` が消える** |
| 詳細記録の非退行 | 従来の点数入力・カード表示が変わらない |
| かんたんモードでの画面遷移 | 記録画面を出入りしてもJSエラーが出ない（`syncAllWheels`） |
| 分析 | かんたん記録が勝率・戦型別などに含まれる |
| CSV | `ゲームカウント` 列が両方の記録方法で埋まる |
