# 設定画面 ＋ プロフィール拡張 設計書

**作成日:** 2026-07-24
**対象:** 卓球記録ノート（一般公開済みPWA）に設定画面を新設し、選手プロフィールを拡張する
**前提:** 既存の `pingpong-app/`（Vercel デプロイ済み・Supabase バックエンド）を改修する

---

## 1. 目的とスコープ

### 解決したい問題

現状、設定画面が存在せず、設定に相当する機能が各画面に散らばっている。

| 今どこにあるか | 内容 |
|---|---|
| ホーム画面ヘッダー右上 | ログアウトボタン |
| 選手切替ドロップダウン内 | 選手の追加・編集 |
| 試合一覧の下 | ご意見・不具合報告リンク |
| ログイン画面のみ | 利用規約・プライバシーポリシー（ログイン後は到達できない） |

また、以下が存在しない。

- **退会（アカウント削除）** — 人に勧める上で信頼面の不足
- **データの持ち出し** — 記録が増えるほど「取り出せない」不安が育つ
- **選手のチーム名・県・性別** — `players` は名前・学年・利き手・戦型の4項目のみ

最後の点により、試合カードは相手側が「名前／チーム（県）」なのに自分側は名前だけで、
**左右非対称**になっている（2026-07 のカード改訂で対称なスコアボードを目指したが、
自分側のデータが存在しないため実現できていない）。

### ゴール

1. 設定画面を作り、散らばった機能を集約してホーム画面をすっきりさせる
2. 選手プロフィールにチーム名・県・性別を追加し、**試合カードを左右対称にする**
3. 退会とデータエクスポートを備え、**人に勧められる状態**にする
4. 相手の性別を記録できるようにし、**性別別の戦績**を分析画面に出す

### スコープ外

- 記録フォームの初期値設定（初期セット数・県・試合種別）— 独立して後から追加できる
- 表示設定（一覧の並び順・ダークモード）
- 通知・リマインダー
- 試合カードへの性別表示 — 詰めたレイアウトを崩さないため出さない

## 2. データモデルの変更

`sql/03-add-profile-fields.sql` を新規作成する。既存の `01-schema.sql` / `02-rls.sql`
は変更せず、差分を追加ファイルで管理する（既存の運用に合わせる）。

```sql
-- 選手プロフィールの拡張
ALTER TABLE players   ADD COLUMN IF NOT EXISTS team   text;
ALTER TABLE players   ADD COLUMN IF NOT EXISTS pref   text;
ALTER TABLE players   ADD COLUMN IF NOT EXISTS gender text;

-- 相手の性別
ALTER TABLE matches   ADD COLUMN IF NOT EXISTS opponent_gender text;
ALTER TABLE opponents ADD COLUMN IF NOT EXISTS gender          text;

-- 退会に必要（現状 accounts には DELETE ポリシーが無い）
DROP POLICY IF EXISTS "users delete own account" ON accounts;
CREATE POLICY "users delete own account" ON accounts
  FOR DELETE USING (id = auth.uid());
```

### 後方互換性

追加列はすべて nullable で、デフォルト値を持たない。したがって：

- 既存の選手・試合・アドレス帳のレコードは変更不要
- `team` が未設定の選手の試合カードは**現状とまったく同じ表示**になる
- `opponent_gender` が未設定の試合は性別別分析の集計から除外される

つまりこの変更は既存ユーザーの画面を壊さず、埋めた分だけ表示が増える。

### 値の取り決め

| 列 | 型 | 取り得る値 |
|---|---|---|
| `players.team` | text | 自由入力（例：J.STYLE） |
| `players.pref` | text | 記録フォームと同じ47都道府県の文字列 |
| `players.gender` | text | `男子` / `女子` / null |
| `matches.opponent_gender` | text | `男子` / `女子` / null |
| `opponents.gender` | text | `男子` / `女子` / null |

性別は文字列で持つ。既存の `hand`（`右利き`/`左利き`）や `opponent_type` が
日本語文字列を直接保存している方式に合わせ、変換層を増やさない。

## 3. 設定画面

### 3.1 到達方法

ホーム画面ヘッダーの「ログアウト」ボタンを**歯車アイコン**に差し替え、
既存の `showScreen()` パターンで `screen-settings` へ遷移する。

ボトムナビには追加しない。日記・記録・分析は毎日使うが設定はめったに開かないため、
最も押しやすい場所を1/4占めるのは費用対効果が悪い。歯車に置き換えることで
ログアウトが設定内へ移動し、**ヘッダーの占有幅も減る**。

設定画面はボトムナビのどの項目にも対応しないため、ヘッダーに「←」を置いて日記へ戻る。

### 3.2 構成

```
⚙️ 設定

【選手】
  体験 太郎（中2）              ›   ← タップで既存の選手編集モーダルを開く
  体験 花子（小5）              ›
  ＋ 選手を追加

【アカウント】
  メールアドレス    xxx@gmail.com     ← 表示のみ
  ログアウト                    ›

【データ】
  試合記録をCSVで書き出し        ›

【アプリについて】
  ご意見・不具合報告             ›
  利用規約                      ›
  プライバシーポリシー           ›
  バージョン              v1.0.0
  ─────────────────
  退会（アカウント削除）             ← 赤字・最下部
```

選手の編集は**既存の選手編集モーダル**（`js/player-edit.js`）を再利用する。
設定画面は入口を提供するだけで、編集UIを二重に持たない。

選手切替ドロップダウンにある「＋選手を追加」は**残す**。設定画面にも同じ入口が
できるが、集約の目的はログアウト・問い合わせ・規約による散らばりの解消であり、
兄弟を追加する近道を奪うことではない。

### 3.3 バージョン表記の出どころ

現状、クライアントに配信されるファイルにバージョンが存在しない
（`package.json` の `1.0.0` はビルド用で配信されない。`manifest.json` にも無い）。

`js/settings-ui.js` に `APP_VERSION` 定数を1つ置き、そこを唯一の出どころとする。
`sw.js` の `CACHE` とは用途が違う（あちらはキャッシュ破棄用の連番）ため兼用しない。
リリース時に手で更新する運用とし、設計書にその旨を明記しておく。

## 4. 選手プロフィールの入力

`js/player-edit.js` の既存フォームに3項目を追加する。新規画面は作らない。

| 項目 | UI | 必須 |
|---|---|---|
| チーム名 | テキスト入力 | 任意 |
| 県 | セレクト（47都道府県） | 任意 |
| 性別 | 男子／女子の2ボタン | 任意 |

性別を2ボタンにするのは、2択でセレクトを使うと「開く→選ぶ→閉じる」の3操作になるため。
既存の利き手選択が同じ2ボタン方式なので、見た目も揃う。

## 5. 試合カードの左右対称化

自分側（`.board-side`）に `.tm` 行を追加し、「チーム名（県）」を表示する。

```
体験 太郎        3  11-8   1     佐藤 健
J.STYLE（新潟）     11-6         青葉中学校（東京）
```

`.board-side .tm` の CSS は相手側で既に使っているものをそのまま流用できるため、
**新規CSSは不要**。`team` が未設定の選手は `.tm` 行を出さず、現状と同じ表示を保つ。

県は括弧内に添える。相手側の書式（`青葉中学校（東京）`）と一致させる。

## 6. 相手の性別と性別別分析

### 6.1 記録フォーム

「対戦情報」セクションに男子／女子の2ボタンを追加する（利き手と同じ見た目）。
**任意項目**で、未選択でも記録できる。

アドレス帳・対戦相手ピッカーから相手を選んだときは、`hand` と同様に
性別も自動で入る。そのため `js/opponents.js` と、ピッカーが返す相手オブジェクトに
`gender` を通す必要がある（過去に `hand` が抜け落ちて同種の不具合が起きているため注意）。

### 6.2 分析画面

既存の4カード（総合勝率／戦型別勝率／年齢カテゴリ別勝率／傾向・強み・課題）に続いて、
5枚目として「性別別勝率」を追加する。既存の `age-grid` と同じ DOM 構造・CSS を使う。

**性別が未設定の試合は集計から除外する。** 「未設定 0%」のような無意味な行を
出すと、かえって読みにくくなる。

### 6.3 設計上の注意

自分の性別（`players.gender`）だけでは分析軸にならない。
「男子相手／女子相手の戦績」を出せるのは `matches.opponent_gender` があるためで、
`players.gender` は現時点では**プロフィール表示用**にとどまる。
将来、複数選手を性別でまとめて見る機能を作るときに活きる。

## 7. データエクスポート

サーバーを介さず、クライアントで Blob を生成して `<a download>` で保存する。
静的サイト構成を崩さない。

- **対象：全選手分**を1つのCSVにまとめる（データの持ち出しが目的なので、
  現在選択中の選手だけでは不足）
- **文字コード：UTF-8 + BOM**。BOMが無いとExcelで開いたとき日本語が文字化けする
- **ファイル名：** `takkyu-note-YYYY-MM-DD.csv`

### 7.1 サービス層にメソッドを追加する必要がある

既存の `matchesService`（`js/main.js`）は**現在の選手専用**で、
`getCurrent()` / `refreshCurrent()` はいずれも `playerState.getCurrentPlayerId()` を
前提としている。全選手を横断して取得する手段が存在しない。

ここで `matches.listByPlayer()` を直接呼んではいけない。デモモードは
`window.matchesService` の差し替えで成立しているため、サービス層を迂回すると
**デモでエクスポートが壊れる**。

したがって、実装側とデモ側の両方に同じメソッドを追加する。

```js
// matchesService（js/main.js）と demo-mode.js の両方に実装する
async getAllForExport() {
  // → [{ player: {name, team, pref, gender}, matches: [...] }, ...]
}
```

クラウド版は選手ごとに `matches.listByPlayer(pid)` を回して集約する（オンライン必須）。
デモ版はメモリ上のデータをそのまま返す。呼び出し側（`settings-ui.js`）は
どちらを使っているか意識しない。

### 列

```
選手名, 試合日, 相手名, 相手チーム, 相手学年, 相手県, 相手性別,
利き手, 戦型, 試合種別, スコア, 勝敗, タグ, メモ
```

タグは配列なので、セル内では `/` 区切りの文字列に変換する。
値にカンマ・改行・ダブルクォートを含む場合は RFC 4180 に従って
ダブルクォートで囲み、内部のクォートを2重化する（メモ欄で実際に起こり得る）。

## 8. 退会（アカウント削除）

### 8.1 方式の選定

`auth.users` の削除には `service_role` キーが必要だが、本アプリは静的サイトで
`api/` を持たず、環境変数にも ANON キーしかない。選択肢は3つあった。

| 方式 | 内容 | 判断 |
|---|---|---|
| Vercel API で完全自動削除 | 正攻法。認証情報まで即時削除 | **却下**：漏洩時にDB全権限を持つ `service_role` キーを新設のAPIに置く必要があり、現在の利用規模に対してリスクが釣り合わない |
| データ全削除＋削除依頼メール | データは即時削除、認証情報は運営が手動削除 | **採用** |
| データ全削除のみ | 「退会」と呼ばない | 却下：信頼面の目的を満たさない |

### 8.2 フロー

1. 設定最下部の「退会（アカウント削除）」をタップ
2. 確認モーダル（**2段階タップ**。既存の試合削除と同じ方式）
   「試合記録・選手・アドレス帳がすべて削除されます。元に戻せません」
3. クライアントから `accounts` の自分の行を DELETE
   → `ON DELETE CASCADE` により `players` → `matches`、`opponents` が連鎖削除される
4. **即座にログアウトする**
5. 運営への削除依頼メールを `mailto:` で起動する
   → **`mailto:` が開かない環境があるため、宛先アドレスを画面上にも文字で表示する**
     （メールアプリ未設定の端末では何も起きず、削除依頼が届かないまま
     ユーザーが「依頼した」と誤解するのを防ぐ）

### 8.2.1 カスケード削除とRLSの関係（実装前に要確認）

`accounts` の行を1件消すだけで `players` / `matches` / `opponents` が連鎖削除される
という前提は、**外部キーの参照アクション（ON DELETE CASCADE）がRLSを迂回する**
という Postgres の挙動に依存している。設計上はこれで正しいが、
第2段の実装時に**テストアカウントで実際に全テーブルが空になることを確認する**。
ここが想定通りでないと、データが半端に残ったまま「削除しました」と表示することになる。

### 8.3 手順4が必須である理由

`accounts` の行を削除してもセッションが残っていると、次回起動時に
`getOrCreateAccount()` が空のアカウント行を**再生成してしまう**（`js/account.js`）。
削除直後に必ずサインアウトし、ログイン画面へ戻す。

### 8.4 正直に書くべきこと

この方式ではメールアドレスが Supabase の認証情報に残る。したがって：

- 確認モーダルに「メールアドレスの削除は運営が対応します」と明記する
- **`privacy.html` に削除手続きを追記する**（データは即時削除、
  認証情報は運営への依頼で削除、連絡先は takkyuu.note@gmail.com）

ここを曖昧にすると「信頼面のため」という本来の目的に反するため、
文言の整備も本作業のスコープに含める。

### デモモードについて

デモデータにも team・pref・gender を入れる。デモは未登録の人が
使い勝手を試す唯一の入口なので、**カードの左右対称と性別別分析が
デモでも見える**必要がある。ここが空だとデモが実物より劣って見える。

デモモードでの設定画面の振る舞いを明示的に決めておく。

| 項目 | デモでの扱い |
|---|---|
| 選手一覧・編集 | 既存方針どおり、追加・編集はトースト「登録すると使えます」で止める |
| メールアドレス | アカウントが無いので行自体を出さない |
| ログアウト | 既存どおり「デモを終了」として機能する |
| CSVエクスポート | **動かす**。メモリ上のデモデータで出力でき、「記録を持ち出せる」体験は登録の動機になる |
| 退会 | 行自体を出さない（消すアカウントが存在しない） |

## 10. リリースの分け方

独立してデプロイ・確認できる3段階に分ける。

### 第1段：スキーマ＋プロフィール拡張＋カード対称

1. **先に** `sql/03-add-profile-fields.sql` を Supabase の SQL Editor で実行する
2. そのうえで以下をデプロイする
   - `players.js` / `player-edit.js` に3項目
   - 試合カードの自分側に `.tm` 行
   - `demo-mode.js` のデモデータ更新

**順序が重要。** 列が存在しない状態で新しいコードをデプロイすると、
選手の保存が Supabase 側のエラーで失敗する。SQL実行 → 確認 → デプロイの順を守る。

**この段だけで、目に見える成果（左右対称のカード）が出る。**

### 第2段：設定画面

- `screen-settings` と歯車アイコン
- 選手一覧・アカウント・アプリについて
- CSVエクスポート
- 退会（＋ `privacy.html` の追記）

### 第3段：相手の性別＋性別別分析

- 記録フォームの性別ボタン
- `matches` / `opponents` への保存、ピッカーでの引き継ぎ
- 分析画面の性別別勝率カード

## 11. テスト

既存の Playwright 一式（`tests/`）が通り続けることを前提に、以下を追加する。
テストは本番URLに対して実行する既存方針に従う。

| 対象 | 確認内容 |
|---|---|
| 設定画面 | 歯車から遷移でき、「←」で日記に戻る |
| プロフィール | チーム名・県・性別を保存 → 再読込後も保持される |
| カード対称 | team を設定した選手のカードに「チーム名（県）」が出る |
| カード後方互換 | team 未設定の選手のカードが従来通り（名前だけ） |
| 性別分析 | 性別付きの試合を記録 → 分析画面の性別別カードに反映される |
| 性別未設定 | 未設定の試合が性別別集計から除外される |
| エクスポート | CSVがダウンロードされ、BOM付きで列が揃っている |

### 退会のテスト方針

**退会は本番E2Eの対象外とする。** 実行するとテストアカウントが消え、
以降のテストが全滅するため。専用の使い捨てアカウントを作って手動で確認し、
確認項目を残す：

1. 2段階タップの確認モーダルが出る
2. 削除後、試合・選手・アドレス帳がすべて消えている
3. 削除後すぐログアウトされ、ログイン画面に戻る
4. 同じメールで再ログインしたとき、空アカウントとして扱われる
   （＝手順4のサインアウトが効いていることの裏取り）
